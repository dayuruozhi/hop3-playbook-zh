# HOP3 中文实践手册：后面的稿件也要认真审

**[开始阅读完整手册 →](https://dayuruozhi.github.io/hop3-playbook-zh/)**

把一批文章交给 AI，前面审得详细，后面却只剩几句套话，怎么办？本手册用中文审稿场景解释 HOP3 如何把要求变成逐篇执行的流程、检查和退回。

由 dayuruozhi 发布的独立实践手册。底层工具和规范见 **[HOP3 项目](https://github.com/hoplogic/hop3)**。

## 可以看到什么

- 一轮完整答复示意：四篇连续展开，八处高亮批注，解释漏项和空泛分析。
- 同一批稿件如何经过检查、退回、补写和最终收集。
- 笔记式记录：目的 → 命令 → 提交内容 → 引擎返回 → 中文解释。
- 可下载的中文稿件和任务规约。
- 三个新 writer 的真实执行实验：逐篇创建、不继承父对话历史，再交回 HOP 收集。

网页可直接阅读，不必安装工具。展开命令和证据可进一步核验；页面本身不执行在线审稿。

## 两组证据分别说明什么

| 内容 | 来源 | 能说明什么 |
| --- | --- | --- |
| 普通智能体完整答复及批注 | 作者构造的示意 | 解释具体的漏项和套话，不是普通模型实测 |
| 四篇逐篇审查 | 作者提供稿件、样稿和质量判定；真实 HOP 引擎执行 | 检查、两次重试、反馈与最终保存如何工作 |
| 三篇新 writer 实测 | 宿主实际创建三个 writer，各自生成报告 | 显式驱动适配能够逐篇启动新 writer 并回收 |

三篇实验不证明长批次不会退化，也未证明 HOP 或新上下文提高审查质量。长批次质量对照尚未进行。

## 文件与核验

- `src/`：中文内容、样式、交互和构建程序。
- `docs/`：GitHub Pages 正式发布目录；包含网页和中文示例包。
- `示例/`：四篇虚构稿件和中文任务规约。
- `证据/`：四篇受控演示的原始命令、返回、状态及录制程序。
- [实测/逐篇新建writer](实测/逐篇新建writer/)：三个 writer 的报告、启动记录和引擎交互。
- `qa/`：浏览器检查程序和发布核验摘要。

历史记录中的绝对路径属于录制环境，保留以便核对，不要求读者建立同名目录。归档核验可以在新机器上运行；重新执行真实 writer 需要接入宿主的 agent 创建能力，不能只运行 Python 驱动脚本。

## 本地构建和阅读

构建只需 Python 3 标准库，不需要安装 HOP：

```sh
python3 src/构建.py
python3 -m http.server 8875 --directory docs
```

浏览器打开 `http://localhost:8875/`。

核验三篇归档的报告和收集结果：

```sh
python3 实测/逐篇新建writer/evidence/verify.py
```

可选：设置 `HOP_REPO` 为 HOP3 本地仓库路径，构建时另行核对引用文件在录制提交中存在。重新录制受控演示前，设置 `HOP_CLI` 为已构建的 HOP CLI 绝对路径，再执行 `python3 证据/录制.py`；这会生成一组新的录制，不是运行质量基准。

浏览器交互检查需要支持内置 WebSocket 的 Node.js 和 Google Chrome。先启动上述本地服务，再运行：

```sh
python3 qa/检查.py 400
python3 qa/检查.py 1280
```

## 发布

GitHub Pages 从 `main` 分支的 `/docs` 发布。修改内容后重新运行构建，把源码及 `docs/` 一起提交推送。发布不依赖本机服务或临时隧道。

本手册保留自有说明和实验边界；关于 HOP3 本身的最新信息，请以[上游仓库](https://github.com/hoplogic/hop3)为准。页面中的技术出处固定到录制版本，便于复核。
