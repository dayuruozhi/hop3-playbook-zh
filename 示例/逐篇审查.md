# Spec: 四篇稿件逐篇审查
标识: zhongwen-article-review
目标: 按同一套六项标准审查四篇稿件，每篇先核对栏目和引文，再审查分析质量，通过后收集报告。

## 输入
- 稿件路径 % line  # 存放四篇虚构稿件的 JSON 文件

## 输出
- 报告合集 % [yaml]  # 按稿件顺序收集的完整审查报告

## 约束
- 每篇报告必须包含核心判断、原文依据、可取之处、关键缺口、待核实问题、处理建议。
- 原文依据至少两条；每条包含原样摘录的引文和针对该引文的解读。
- 缺口与问题必须针对本篇，处理建议须与现有证据相称，不得用套话代替分析。
- 不补造原文未提供的事实，不能把同时发生的变化直接写成因果关系。
- 原文保持不变；每篇最多允许一次重试，仍不通过则保留失败信息供人工处理。

## 步骤
1. [探索] 读取稿件清单
  - ← 稿件路径
  + → 稿件清单 % [yaml]
  > ```hop_python
  > 稿件清单 = parse_json(read(path: 稿件路径))
  > ```

2. [循环 遍历 当前稿件 于 稿件清单, 收集 本篇报告 入 报告合集] 逐篇审查
  + → 报告合集 % [yaml]
  2.1. [子任务 重试=1] 完成本篇报告及检查
    - ← 当前稿件
    + → 本篇报告 % yaml
    2.1.1. [推理] 按六项标准写出本篇报告
      - ← 当前稿件
      + → 本篇报告 % yaml
      > 生成包含六个中文字段的对象：核心判断、原文依据、可取之处、关键缺口、待核实问题、处理建议。
      > 原文依据是列表，每条包含引文与解读。其余字段为文字。
      > 说明原文哪些话支持什么结论、还缺什么依据，不得把读后概述当作审查，不得只写“内容清晰、建议完善”。
    2.1.2. [检查] 核对栏目、引文和解读是否齐全
      - ← 当前稿件, 本篇报告
      + → 栏目通过 % bool
      + → 栏目说明 % text
      > ```hop_python
      > 必备栏目 = ["核心判断", "原文依据", "可取之处", "关键缺口", "待核实问题", "处理建议"]
      > 栏目齐全 = all([栏目名 in 本篇报告 for 栏目名 in 必备栏目])
      > 栏目通过 = False
      > 栏目说明 = "审查报告缺少必备栏目。请补齐六项内容，原文依据至少两条，每条附引文与解读。"
      > if 栏目齐全:
      >     正文齐全 = all([len(strip(本篇报告[栏目名])) > 0 for 栏目名 in ["核心判断", "可取之处", "关键缺口", "待核实问题", "处理建议"]])
      >     依据足够 = count(本篇报告["原文依据"]) >= 2
      >     if 正文齐全 and 依据足够:
      >         引文可核 = all(["引文" in 依据 and "解读" in 依据 and len(strip(依据["引文"])) > 0 and len(strip(依据["解读"])) > 0 and 依据["引文"] in 当前稿件["正文"] for 依据 in 本篇报告["原文依据"]])
      >         栏目通过 = 引文可核
      >         栏目说明 = "六项内容齐全，至少两条引文能在原文找到，且都有解读。" if 引文可核 else "请使用能在本篇原文找到的引文，并为每条引文补充解读。"
      >     else:
      >         栏目说明 = "六个栏目都须有内容，原文依据至少两条且附解读。"
      > ```
    2.1.3. [检查 终检] 判断分析是否具体且有依据
      - ← 当前稿件, 本篇报告
      + → 质量通过 % bool
      + → 质量说明 % text
      > 判断引文解读是否说清支持范围，缺口是否针对本篇方法或信息，追问是否回应这些缺口，处理建议是否与证据相称。
      > 即使栏目齐全，也要退回泛泛的评价、无实际指向的追问和原文不支持的结论。
      > 代码检查只能核对栏目与引文，不能代替此处的实质判断。未通过时指出具体缺口。
